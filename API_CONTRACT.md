# API Contract

Base path: `/api/v1`.

Initial resource families:

- `GET /books`, `GET /books/{id}`
- `GET /artifacts`, `GET /artifacts/{id}`
- `GET /themes`, `GET /collections`
- `GET /articles`, `GET /articles/{id}`
- `GET /learning`, `GET /learning/{id}`
- `GET /programs`, `GET /programs/{id}`
- `GET /baraza/concepts`, `/baraza/inquiries`, `/baraza/texts`, `/baraza/thinkers`
- `GET /media/{id}`

The bootstrap may expose only a health endpoint and fixtures initially; these resource contracts are the roadmap, not permission to create speculative endpoints.

## Contract rules
- Use stable opaque IDs.
- Return explicit relationship identifiers or nested representations according to the approved schema; never require clients to scrape labels.
- Use HTTP semantics consistently: 200 for successful reads, 404 for missing resources, 422 for invalid request data.
- Collection endpoints must define pagination before production-scale data is introduced.
- Query/filter semantics must be documented and deterministic.
- Breaking changes require a new API version.

OpenAPI generated by FastAPI is the executable API contract and should be checked in CI for unintended changes once the public resource surface is implemented.
